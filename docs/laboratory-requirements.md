# Lyrics Plus v2.3.0 实验室功能需求说明书

- 状态：已确认，作为后续任务执行基线
- 目标分支：`dev/2.3.0`
- 文档范围：需求、边界、接口约束和阶段验收；不包含本期代码实现

## 一、目标与范围

在“高级工具”中增加“实验室”，以一套统一同步服务支撑三个方向：

```text
高级工具
└── 实验室
    ├── 多端歌词同步      开发中
    ├── 网页端主题平台    开发中
    └── 硬件歌词屏        开发中
```

本期完成：

- 统一歌曲、封面、歌词、播放状态、进度和频谱数据模型；
- 服务端与 App 客户端；
- 局域网发现、手动连接、鉴权、重连和客户端管理；
- 网页服务、访问令牌和二维码；
- 网页主题包运行时、主题 SDK 和基础 Demo；
- 公共播放遥控器。

本期不完成：

- 硬件歌词屏实际连接；
- 蓝牙、串口或硬件协议；
- 内置 AI 主题生成；
- HTTPS/WSS 或公网安全托管；
- 音量、循环模式控制；
- App 客户端和硬件端主题包。

## 二、产品需求

### 1. 统一同步原则

服务端必须是实际播放音乐的电脑，也是唯一可信状态源。

统一状态包含：

- 歌曲 ID、名称、歌手、专辑和播放器来源；
- 封面资源 ID；
- 原文、翻译、罗马音、逐字时间轴和歌词版本；
- 播放、暂停、总时长和当前位置；
- 服务端观测时间；
- 16 段音频频谱及频谱状态。

客户端不得自行搜索、替换或合并歌词。现有“切换歌词”功能仍由服务端执行，切换完成后推送新歌词给所有客户端。

客户端连接成功或重连成功后，服务端首先发送完整状态快照，再发送增量事件。客户端根据服务端位置和时间戳平滑推进歌词进度，并定期用服务端状态校准。

封面按 `artworkId` 从服务端资源接口获取并缓存，不随高频状态重复传输。频谱沿用现有约 30 FPS、16 段数据，仅由服务端分析音频。

### 2. 服务端与客户端生命周期

实验室页面使用“服务端 / 客户端”分段选择器：

- 应用启动时不弹出角色选择；
- 保存上次角色及全部配置；
- 运行期间切换角色前必须先停止当前角色；
- “随应用启动”开启时自动启动上次角色；
- 关闭时只保存配置，由用户手动启动。

服务端配置：

- 默认名称为设备名称，可修改；
- 固定生成并持久化稳定服务端 ID；
- 默认端口 `47123`，允许修改；
- 可开启或关闭局域网发现；
- 可启用用户自定义连接密码，也可无密码开放；
- 无密码时只显示风险提示，不施加额外限制；
- 全局控制防抖默认 1 秒，可修改；
- 网页服务独立开关，默认关闭并持久化。

客户端配置：

- 默认名称为设备名称，可修改；
- 固定生成并持久化稳定客户端 ID；
- 可保存多个历史服务端；
- 自动启动时只连接上一次使用的服务端；
- 保存服务端 ID、地址和密码；
- 断线后最多自动重试 3 次；
- 失败后保留在“最近连接”列表，并允许一键重试。

### 3. 局域网发现和鉴权

使用 mDNS/Bonjour 广播 `_lyrics-plus._tcp.local.` 服务，广播内容仅包含：

- 服务端 ID；
- 服务端名称；
- 地址和端口；
- 协议版本；
- 是否需要密码；
- 网页服务是否可用。

密码不参与广播。

客户端体验类似连接 Wi-Fi：

1. 自动扫描服务端；
2. 用户手动选择；
3. 需要密码时输入密码；
4. 连接成功后保存；
5. 服务端 IP 改变时，根据稳定 ID 更新地址并重连。

关闭局域网发现后，服务端不出现在列表中，但仍允许通过 `IP/域名[:端口]` 手动连接。

服务端修改密码后：

- 现有 App 客户端会话失效；
- 已保存的旧密码不能继续连接；
- 客户端提示密码错误并要求重新输入。

### 4. 客户端管理

服务端只管理 App 客户端，不管理网页浏览器会话。

客户端列表同时显示在线和离线记录，包括：

- 客户端名称；
- 客户端 ID；
- 在线状态；
- 最近连接时间。

服务端可以：

- 踢出在线客户端；
- 删除离线客户端记录。

踢出只终止当前会话，不构成永久封禁；客户端使用当前有效密码可以重新连接。

### 5. 播放控制与防抖

复用现有公共播放能力：

- 播放；
- 暂停；
- 播放/暂停切换；
- 上一首；
- 下一首；
- 拖动进度。

底层继续复用现有 `playerService`、`playbackApi` 和 Rust 播放控制，不建立第二套播放器逻辑。

所有远程控制进入服务端统一控制网关：

- 客户端前端先限制连续点击；
- 服务端对所有客户端、所有指令执行全局防抖；
- 防抖窗口内只保留最后一条指令；
- 新指令到达时重新计算窗口；
- 被合并的指令不返回结果；
- 最终实际执行的指令返回成功或错误；
- 执行成功后广播最新状态。

在现有主题切换按钮所在工具区增加“播放遥控器”入口，弹窗复用相同控制能力。

### 6. 网页服务和访问令牌

网页服务依赖服务端角色，但拥有独立开关：

- 关闭时不提供网页地址，不影响 App 客户端同步；
- 开启时提供访问地址、复制链接和二维码；
- HTTP 与 WebSocket 使用同一个端口；
- 第一阶段不强制 HTTPS/WSS；
- 公网使用风险由用户自行承担。

网页端不输入服务端密码，而是使用链接中的随机访问令牌：

- 令牌首次启用网页服务时生成；
- 持久化保存，重启后不变；
- 二维码和复制链接均携带令牌；
- 用户可以重置令牌；
- 重置后旧链接和旧网页会话全部失效；
- 网页令牌和 App 连接密码互不影响。

网页浏览器不显示在客户端管理列表中，也不设置客户端名称。

## 三、网页主题平台

### 1. 主题包目录

主题目录固定为应用数据目录下的 `themes/`。

目录规则：

```text
themes/
├── default-theme-a/
├── default-theme-b/
└── custom-theme/
```

- 基础 Demo 和自定义主题放在同一目录；
- 每个子目录代表一个主题；
- 只接收外部构建完成的文件夹；
- 不支持 ZIP 自动解压；
- Lyrics Plus 不安装依赖、不执行主题构建；
- 用户可以直接添加、替换或删除任意主题；
- 打开网页或手动刷新主题列表时重新扫描。

每个主题必须包含 `manifest.json`，最低字段为：

```json
{
  "id": "theme-id",
  "name": "主题名称",
  "version": "1.0.0",
  "entry": "index.html",
  "sdkVersion": "1"
}
```

主题 ID 必须唯一，入口必须位于主题目录内部。无效清单、路径越界或入口缺失的主题不加载。

### 2. 主题选择与运行

主机只决定有哪些主题可用，不强制所有用户使用同一主题。

每个浏览器：

- 独立选择当前主题；
- 将主题 ID 保存在浏览器本地；
- 不影响其他访问者；
- 已选主题失效时回退 `basic-demo`；该目录被删除后不自动恢复。

网页主壳负责主题列表、主题切换和错误回退。主题在占满可视区域的沙箱 iframe 中运行：

- 使用 `sandbox="allow-scripts"`；
- 不允许直接访问网页主壳 DOM；
- 切换时销毁旧 iframe 并创建新 iframe；
- 通过 `postMessage` 与 SDK 通信；
- 主题可使用任意构建技术、Three.js 和自带资源；
- 主题内部设置、样式和持久化完全由主题作者负责。

基础 Demo 是一个普通主题：

- 目录为仓库中的 `themes/basic-demo/`，首次运行时复制到应用数据目录；
- 出现在主题列表中，可以被选择和复制参考；
- 直接展示 SDK 的完整状态及播放控制；
- 被用户删除后不自动恢复，网页没有可用主题时显示提示。

### 3. 主题 SDK

提供框架无关、可独立引入的 `@lyrics-plus/theme-sdk`，并由网页服务暴露对应的浏览器 ESM 版本。

SDK v1 只负责：

- 获取当前完整状态；
- 订阅歌曲、歌词、播放、进度和频谱事件；
- 调用播放控制；
- 接收实际执行命令的错误；
- 管理与网页主壳的连接生命周期。

SDK 不负责：

- 主题扫描；
- 主题列表；
- 主题切换；
- 主题配置；
- 主题样式和布局。

SDK v1 发布后保持向下兼容：

- 旧字段和事件不随意修改；
- 新能力优先通过新增字段或方法提供；
- `sdkVersion` 用于兼容提示，不因普通小版本差异拒绝加载。

同时提供：

- SDK API 说明；
- `manifest.json` 规范；
- 最小主题 Demo；
- 面向开发者或 AI 的主题制作说明。

Lyrics Plus 不内置 AI 生成服务。

## 四、技术架构与公共接口

### 1. Rust 统一服务

新增独立的 Laboratory Runtime，职责分为：

- 状态 Hub：汇总当前播放、歌词、封面和频谱；
- Server Runtime：HTTP、WebSocket、鉴权、客户端管理；
- Client Runtime：发现、连接、重连和远程状态；
- Discovery：mDNS 发布和扫描；
- Theme Runtime：目录扫描、静态资源和清单校验；
- Command Gateway：全局防抖和现有播放控制转发。

推荐依赖：

- `axum`：HTTP、WebSocket 和静态资源；
- `tower-http`：主题资源服务；
- `mdns-sd`：局域网发现；
- 继续使用现有 Tokio 运行时和广播通道。

### 2. 协议 v1

统一使用 JSON WebSocket 消息：

```text
ws://主机:端口/ws
```

公共消息外层包含：

- `protocolVersion`；
- `type`；
- `requestId`（命令类可选）；
- `timestampMs`；
- `payload`。

最低消息类型：

- `client.hello`：App 客户端名称、ID 和密码；
- `web.hello`：网页访问令牌；
- `session.ready`：鉴权成功和完整状态；
- `state.snapshot`：完整状态；
- `playback.changed`；
- `lyrics.changed`；
- `spectrum.state`；
- `spectrum.frame`；
- `playback.command`；
- `command.result`；
- `session.error`。

歌词和播放状态事件使用现有 TypeScript/Rust 类型作为源定义，避免前后端再维护一套不同字段。

频谱继续按订阅者数量懒启动：没有 App/Web 消费者时不额外启动网络频谱推送。
外部 WebSocket 的 `spectrum.frame` 每个连接最多每 100ms 推送一次，窗口内合并为最新帧；本机频谱采集和 Tauri 窗口事件仍保持约 30 FPS。

### 3. 状态源切换

抽象统一播放/歌词数据源：

- 服务端角色使用当前本机 Tauri 播放与歌词运行时；
- 客户端角色使用远程状态；
- 客户端连接期间禁止本地歌词自动搜索；
- 客户端断开时显示断开状态，不回退到本机播放器；
- UI 和歌词窗口继续消费同一个统一 Provider，避免各窗口判断角色。

### 4. 配置和持久化

将配置 schema 从当前版本递增，并新增 `laboratory` 配置段：

- 角色；
- 随应用启动；
- 服务端名称、端口、发现开关、网页开关、防抖时间；
- 客户端名称和上次服务端 ID。

敏感信息不进入可导出的 `config.json`：

- 服务端连接密码；
- 网页访问令牌；
- 客户端保存的服务端密码；
- 稳定服务端/客户端 ID。

敏感信息使用独立、原子写入且权限限制为 `0600` 的 Laboratory 凭据文件。已知服务端、在线/离线客户端记录使用现有本地存储层保存。

## 五、执行阶段

- 增加 Laboratory 配置、运行状态、协议类型和凭据存储；
- 建立统一状态快照；
- 将现有播放、歌词、封面和频谱接入状态 Hub；
- 增加配置迁移和默认值。

完成判定：旧配置可正常读取，新配置可保存，完整状态与现有本机界面一致。

### 阶段 2：服务端运行时

- 完成 HTTP/WebSocket 服务；
- 实现 App 密码鉴权、稳定服务端 ID 和全局防抖；
- 实现 mDNS 发布；
- 实现在线/离线 App 客户端管理；
- 实现密码修改、踢出和忘记客户端。

完成判定：另一进程能够连接、收到完整状态、控制播放并持续接收更新。

### 阶段 3：App 客户端

- 实现 mDNS 扫描和 Wi-Fi 式服务端列表；

- 将 App 播放、歌词窗口和频谱切换到远程数据源。

完成判定：客户端不自行搜索歌词，服务端切歌或切换歌词后所有界面同步更新。

### 阶段 4：实验室界面和遥控器

- 增加 `/settings/laboratory` 路由和高级工具入口；
- 实现服务端/客户端分段页面；
- 实现启动、停止、自动启动、发现、密码、端口和防抖配置；

- 增加公共播放遥控器弹窗；
- 补齐全部现有语言的文案。

完成判定：所有运行状态和配置均可在界面完成，不需要修改配置文件。

### 阶段 5：网页服务和主题运行时

- 实现网页服务独立开关；
- 实现随机访问令牌、二维码和重置；

- 实现 `themes/basic-demo` 普通主题和主题加载错误提示。

完成判定：不同浏览器可使用不同主题，基础 Demo 被删除后网页显示无可用主题提示。

### 阶段 6：主题 SDK 和开发资料

- 完成 SDK v1、浏览器 ESM 产物和类型声明；
- 完成状态订阅、控制调用和错误反馈；
- 提供主题包规范和最小开发 Demo；
- 明确向下兼容规则。

完成判定：外部项目构建出的主题文件夹放入 `themes/` 后可被扫描、切换并正常使用统一数据和播放控制。

### 阶段 7：硬件扩展位

- 仅保留硬件适配器接口和协议版本能力；
- 不实现 Wi-Fi、蓝牙或具体硬件模块；
- 菜单中继续显示“开发中”。

## 六、完成判定场景

不新增自动化测试用例，也不把构建作为计划步骤；按以下场景确认功能完成：

- 旧版本配置升级后，实验室默认不自动运行；
- 服务端可被发现，也可关闭发现后通过地址连接；
- 有密码、无密码、密码修改三种连接行为符合需求；
- 服务端 IP 改变后，客户端根据稳定 ID 重新连接；
- 客户端断线只重试 3 次，并保留最近连接；
- 多个客户端同时发指令时，全局 1 秒防抖只执行最后一条；
- 新客户端连接后立即获得歌曲、封面、完整歌词、进度和频谱状态；
- 服务端现有“切换歌词”后，所有客户端同步替换；
- 网页服务关闭不影响 App 客户端；
- 网页令牌重置后旧网页全部失效；
- 网页用户不出现在客户端管理列表中；
- 不同浏览器可独立选择主题；
- 无效主题自动回退 `basic-demo`，该主题不存在时显示无可用主题提示；
- 主题 iframe 不能直接访问网页主壳；
- SDK 可以接收统一状态并调用既有播放控制；
- 随应用启动分别能恢复服务端或客户端角色。

## 七、固定默认值与约束

- 目标分支：`dev/2.3.0`；
- 协议版本：`1`；
- SDK 主版本：`1`；
- 默认服务端端口：`47123`，允许修改；
- 默认服务端防抖：`1000ms`；
- 默认网页服务：关闭；
- 默认随应用启动：关闭；
- 默认连接密码：关闭；
- 默认局域网发现：开启；
- 自动重连次数：3；
- 主题目录：应用数据目录下 `themes/`；
- 传输方式：HTTP + WebSocket，不强制 TLS；
- 硬件接入：不在本期实现。
